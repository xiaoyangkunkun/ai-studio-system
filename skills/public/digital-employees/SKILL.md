# 数字员工调度(Digital Employees)

## When to Use
- 用户提到「员工」「数字员工」「调研」「写文章」等需要独立 profile 执行的任务
- 主 agent 需要把任务分发给 researcher/writer 员工

主 Agent(微信实例)按需调度员工 profile 干活的统一流程。员工 = Hermes Profiles(分身),非独立安装、非常驻 gateway。

## 新员工入职流程(老大 2026-08-13 确认)
**阶段0 决策**:定岗位名+员工名(岗位·名字)、profile 名、模型 → 老大已批准扩编建议书
**阶段1 建档**:hermes profile create --clone → 写 SOUL(角色/职责/流程/工作室铁律:不编造·条目式·带来源 + 岗位规矩)→ **建产出目录 `vault/工作室产出/<岗位·名字>/`(新员工统一归口,2026-08-14 定)** → 建 vault/工作室/员工/XX员·名字.md(职责/SOUL摘要/技能/产出目录/迭代日志 v0.1)
**阶段2 配技能**:挂载公共库(external_dirs)→ 私有技能按归属规则 → MCP 按岗位配到其 config
**阶段3 组织更新**:组织架构.md 加人头+职责表(产出目录列 = vault/工作室产出/<岗位·名字>/)→ 任务交接(分流规则加新岗位)→ 定时任务归属调整(如涉及)
**阶段4 验证**:冒烟测试(能跑/公共库可见/私有技能加载)→ 测试分发链路(狗头军师→员工→产出回传)→ 用量统计接入
**阶段5 汇报**:向老大汇报名字/职责/成本/试运行安排 → 更新记忆+本技能员工清单
**阶段6 试运行2周**:观察质量/频率/成本 → 迭代日志记录 → 评估:达标转正(正式入分流)/优化/劝退(归档 profile)
(自动覆盖:技能健康检查、知识库目录、备份体系)

## 技能推荐机制(老大 2026-08-13 定)
- 21:30 cron 主控=狗头军师,覆盖**全员**(profile list 动态获取,新员工自动纳入)
- 每人每天 3-5 个;岗位贴合(狗头军师通用/知远调研/墨白写作)
- **推荐输出四大板块(对应技能四条去向)**:
  1. 📦 **公共库推荐**:通用技能,全员可用 → 装公共库
  2. 🤖 **狗头军师专属推荐**:调度/管理/审核/协作类(如 kanban 协作板、任务管理)→ 装公共库但标注"狗头军师用途"
  3. 🧑💼 **员工专属推荐**:按岗位分(知远调研/墨白写作)→ 装对应员工私有库
  4. 🚀 **新方向/热门储备**:新奇热门、暂不用但值得关注 → 标记为未来新员工的技能储备(可关联扩编机制,如"数据员/运营员/客户专员"方向)
- **推荐判断(三步筛选,缺一不可)**:
  1. **重复对比**:与现有功能重复 → 新技能**优于**现有才推(标注「建议替换:XX」);一模一样或更差 → 跳过
  2. **适合度**:不重复也要评估**适不适合该成员**(岗位贴合/使用场景/真实需求)→ 不适合 → 跳过
  3. **价值**:适合的再看价值——补真实缺口 → 推荐;新方向/热门趋势 → 推荐并标注「新方向」(哪怕暂用不上,值得关注)

## 员工扩编机制(老大 2026-08-13 提出)
- 狗头军师持续观察任务分布,发现"单一性高"的工作 → 向老大推荐新招员工
- 触发建议条件(满足 2 条以上):
  - 某类型任务每周 ≥3 次,且流程固定、可标准化
  - 该类型任务每周占用 >2 小时(狗头军师或现有员工)
  - 新岗位职责边界清晰,不与现有员工重叠
  - 按需启动的 token 成本可接受
- 流程:狗头军师在周复盘/月报提「扩编建议书」(岗位名+职责+技能包+预估成本)→ 老大批准 → 建 profile+SOUL+技能 → 试运行 2 周 → 评估去留
- 架构预留岗位:数据员、运营员、客户专员(见 vault/工作室/组织架构.md)

## 任务自动分流(老大无需指定,狗头军师按规则分配)
- **落地类任务先调研再动手(2026-08-15 CSDN 教训,老大定)**:涉及"部署/接入/自动化"等落地任务,先派知远调研(找现成方案/逆向根因/对比选型),拿到可落地结论再实施;禁止直接埋头试错(CSDN 案例:直接部署 csdn-mcp 踩坑 7+ 轮,调研后 API 直调一次成功)
- 调研/检索/资料收集/技能挖矿 → **知远**(researcher);知远检索**优先用 Exa MCP**(web_search_exa/web_fetch_exa,2026-08-15 配置,免费额度每月 $10),军师自己日常搜索保持 searxng+tavily 不动 Exa 额度
- 写作/文案/润色/公众号 → **墨白**(writer)
- 代码/脚本/开发/调试/代码审查 → **技术员·Claude**(外部引擎:SSH→Windows 上 Claude Code;需 Windows 在线,深夜任务提前叫老大开机)
- 需对话记忆/隐私/审核/微信推送 → **狗头军师自己做**
- 定时任务 → 按 vault/工作室/组织架构.md 的任务归属表
- 模糊/新类型 → 狗头军师先做或问老大
- **派活机制 v1(老大 2026-08-15 定,详见组织架构.md「派活机制 v1」)**:①可用性矩阵——深夜只派服务器侧(知远/墨白/Gemini),Kimi/DeepSeek 派前探测,不可用走主模型 ②材料传递——vault 材料给路径让顾问读原文(零转述)、别处直传原文、禁止压缩长材料进 prompt(压缩=输出简陋)③任务匹配——调研知远/长文墨白Kimi/海外Gemini/推理DeepSeek/代码技术员/Windows小端/复盘总结军师自己 ④派单前4问:我有上下文吗(有就自己做)/顾问可用吗/材料在哪(路径或直传)/输出怎么回(长文落盘+摘要)
- **来源标注铁律(老大 2026-08-15 定)**:凡顾问/员工提供或加工的资料,产出文档必须标注来源顾问,格式 `(来源:海外顾问·Gemini/临时顾问·Kimi/DeepSeek,YYYY-MM-DD,经 ask_*.py 调用)`;自有检索标 `(来源:XX检索,日期)`;不标视为违规。员工可跨调顾问(知远/墨白可自行调 ask_gemini.py),材料直接读 vault 原文,零压缩
- **派活省的是能力不是 token(老大 2026-08-15 纠正)**:军师有上下文的活(复盘/日报/总结)自己干,组织 prompt + 读回复 = 双倍 token;只有能力溢价任务才派,长输出落盘只回传摘要
- 老大可随时指定「这个给XX做」;小任务/员工忙 → 狗头军师自己做(成本判断)

## 调用方式

```bash
# 前台(短任务)
hermes -p researcher chat -q "任务描述" 

# 后台(长任务,完成通知)
terminal(command="hermes -p researcher chat -q '任务'", background=true, notify_on_complete=true)

# wrapper 别名(wrapper 在 ~/.local/bin/,需 PATH 含 ~/.local/bin)
researcher "任务"
writer "任务"
```

## 调度规则
- 员工**不常驻**:按需启动、跑完即退、内存自动释放(服务器仅 1.6G 内存,严禁常驻多个 gateway)
- 任务下发要**自包含**:员工无当前会话上下文,须写清背景/目标/输出位置/格式
- 产出必须落在 vault 对应目录(三端同步,用户随处可看)
- 用户反馈 → 立即改对应 profile 的 SOUL.md 或沉淀 skill,不等周复盘

## 迭代机制
- **成长记录铁律(2026-08-14 老大定)**:每次给员工派活/交付后,**必须更新该员工档案页的「📈 成长记录」小节**(任务内容/表现/反馈/技能增强/里程碑);没有成长记录小节先补建。这是硬规则,靠调度流程执行,不靠记性。
- **自我复盘惯例(2026-08-15 老大定)**:每单交付后,**员工自己写复盘**(军师只审阅归档,不代写):①学到了什么 ②反馈模式(老大/军师要什么)③暴露的问题与改进 ④下次 checklist(5-8 条)⑤一句话宣言。存 `vault/复盘/员工/<岗位·名字>/YYYY-MM-DD-<主题>经验总结.md`;多轮迭代的大单必写,简单小单可合并到周复盘时补;军师审阅后归档,同步成长记录。
- 每次任务后:可复用方法沉淀为 skill(员工自己或主 agent 代写)
- 用户反馈是最优先级改进指令
- 周复盘(可选 cron):评估员工输出质量,更新 SOUL/技能
- **技能健康检查(每月1号 10:00 cron)**:读 .usage.json 使用统计,90 天未用的沉淀技能评估后**先推候选清单给用户,用户确认后才归档**(用户 2026-08-13 指定半自动);归档到 .archive 可恢复
- **烂技能即时触发(不等月度)**:用技能出错/结果差 → 记入 ~/.hermes/data/skill_issues.json(count/reasons/last_error_at);**累计 3 次 → 当场推微信给用户**(技能名+原因+建议归档/修复),用户确认后处理;月度健康检查读该文件把 count>=3 的并入候选清单

## 技能架构(公共 + 私有)
- **公共库 = 主技能库** `~/.hermes/skills/`:主大脑本地使用,所有员工通过 config 的 `skills.external_dirs` 挂载同一目录 → 一套通用技能全团队共用,改一处全生效
- **私有库 = 各 profile 的 skills/**:员工独有技能放这里(目前为空,等沉淀)
- **优先级:私有 > 公共**:加载顺序本地在前,同名技能私有库赢,员工可覆盖公共技能
- **公共库对员工只读**:curator/自动维护不会改动外部目录,员工不会污染公共库
- **晋升机制**:员工私有技能 → 主 agent 每周复盘审核 → 通用性达标搬入公共库(广播全团队),不通用留私有
- **新技能归属判断(用户 2026-08-13 定)**:
  - 通用基础能力(人人要用:搜索/提取/文档/去AI味)→ **公共库**
  - 领域专属(只有某员工用:公众号/营销文案/调研流程/学术检索)→ **对应员工私有库**
  - 半通用(主大脑+个别员工都用)→ 公共库(去 AI 味先例)
  - 判断不清 → **先问用户再装**

## 沉淀机制(用户习惯:沉淀全进知识库)
1. 成果 → vault/工作室产出/<岗位·名字>/ 子目录(三端同步;按需建主题子目录,4 层封顶内,2026-08-15 定)✅
2. 员工独有技能 → 通用性审核后并入主技能库(~/.hermes/skills/,镜像进 vault/技能库/);档案页 vault/工作室/员工/<名字>.md 同步更新技能清单
3. 迭代日志 → 每次改进员工(改 SOUL/技能/模型)必须在本页追加一行:版本 | 改了什么 | 为什么(用户反馈驱动)
4. 员工记忆里的关键沉淀 → 值得文档化的抄进档案页

## 陷阱
- `~/.local/bin` 不在默认 PATH:用 `hermes -p <profile>` 或先 export PATH
- profile 用量计入各自 state.db,与主实例分开(用量结算脚本如按主库统计,需单独适配)
- 员工 .env/config.yaml 克隆自主实例,改 key 时注意 profile 独立文件
