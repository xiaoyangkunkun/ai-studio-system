# 知远调研工作流（含 wiki ingest + PDF 交付）

## 流程

```
收到调研任务
    ↓
调研（搜索/提取/整理）
    ↓
写调研报告 → 存 vault/工作室产出/方案架构师·知远/调研报告/
    ↓
Ingest 到 wiki：
    1. 原始报告 → wiki/raw/调研报告/
    2. 关键结论 → wiki/entities/（更新相关实体页）
    3. 新概念 → wiki/concepts/（创建概念页）
    4. 对比结论 → wiki/comparisons/（创建对比页）
    5. 更新 wiki/index.md
    6. 追加 wiki/log.md
    ↓
转 PDF → 发微信给老大
    ↓
PDF 发完 → 删 PDF（MD 永久保留在产出目录）
```

## 两个存储的区别

| 位置 | 定位 | 谁用 | 生命周期 |
|---|---|---|---|
| `vault/工作室产出/方案架构师·知远/` | 团队产出记录 | 老大（看 MD）、晨报统计 | 永久保留 MD |
| `vault/wiki/raw/调研报告/` | 知识资产 | AI 团队（检索/引用） | 永久保留，只读不改 |
| PDF（临时） | 微信交付物 | 老大（手机看） | 发完即删 |

## 派活时必须包含的 prompt 要素

派知远调研时，prompt 必须包含：
1. **调研方向**：具体要查什么
2. **必读材料**：服务器本地有哪些参考文件
3. **产出路径**：`写报告到 ~/vault/工作室产出/方案架构师·知远/调研报告/xxx.md`
4. **格式要求**：中文、条目式、每条结论带来源

⚠️ 如果不指定产出路径，知远可能只返回文字不存文件（8/16 已踩坑：3个任务缺文件）

## Ingest 规则

| 内容类型 | 存到哪里 | 举例 |
|---|---|---|
| 原始报告 | wiki/raw/调研报告/ | MiMo API 能力调研报告.md |
| 工具评测结论 | wiki/entities/工具名.md | MiMo.md、DeepSeek.md |
| 技术方法 | wiki/concepts/技术名.md | 语音交互.md、Memory MCP.md |
| 对比结论 | wiki/comparisons/A vs B.md | MiMo vs DeepSeek.md |

## 注意事项

- raw 文件只读不改，修正写在整理页
- 每次 ingest 必须更新 index.md 和 log.md
- 实体页有则更新，无则新建
- 对比页引用 raw 来源
