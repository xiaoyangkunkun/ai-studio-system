# 日志区与域名接入改造(2026-08 实战记录)

## 一、vault 日志区(每日/每周时间线)

### 结构
```
vault/日志/
├── README.md          ← 规则说明
├── 每日/YYYY-MM-DD.md ← 晚间复盘 22:00 双写
└── 每周/YYYY-Www.md   ← 周复盘 周日 21:00 双写
```
- 两个文件夹分开(用户明确要求区分每日/每周)。
- 日志区定位 = 时间线(md 好读,手机 Obsidian 直接翻),Notion 同步留底(管理备份)。

### 防污染三件套(日志区不参与知识库)
1. `kb_inventory.py` SKIP_DIRS 加 `日志`
2. 知识库整理 cron(23:00)prompt 加"跳过 日志/ 目录"
3. 日志区独立于 concepts/entities,知识索引不收它

### 条目式复盘模板(用户明确偏好:严禁大段文字)
每日:
```
## 今日概述
- 每条一行按主题分行(知识库:.../ 系统:.../ 生活:...),3-6 条
## 见闻与收获
- 每条带小图标(🤖 AI / 🔧 工具 / 🌤️ 天气 / 💡 心得),2-5 条
## 明日计划
- [ ] 事项(Obsidian 可打勾),1-4 条
```
每周:本周概览(按天/主题,每条一行)/ 关键收获 / 经验沉淀 / 下周计划(`- [ ]` 任务框)

### 写入流程:默认写入 + 可修改重写(用户 8/12 明确)
- 复盘生成后**直接写入**(Notion + vault 日志区),再推送微信完整预览。
- 用户说"要改哪里"才重写覆盖;**不要等待用户确认** —— 用户可能忘记回复,等确认会丢日志。
  用户原话:"你先默认写入,我如果有说要修改的话,你再重新写入(因为我可能会忘记回复)"。
- 用户最初要求"先过目再写入",后因会忘记回复改为默认写入 —— 两者都要知道,最终以"默认写入+可修改"为准。
- 双写要点:
  - Notion 写入前先查该数据库当天/本周是否已有记录(有则更新,避免重复)
  - 日志区 md 用 write_file 覆盖当天文件
  - Notion MCP 不可用时日志区 md 仍要写
- 用户对 Notion 复盘的"乱"的反馈 → 根因是段落式排版,条目式解决。

## 二、域名接入改造(IP → 域名)

### 场景
申请域名({{SYNC_DOMAIN}})后,把全系统对公网 IP 的引用改为域名。
核心价值:服务器换 IP 时三端 Syncthing 配置零改动(只改 DNS 解析)。

### 流程(已验证)
1. 申请域名 + 实名认证(阿里云万网,.cn 便宜)
2. DNS 解析:sync 子域 A 记录 → 公网 IP
   - **22000 端口走域名无需备案**
   - 网页/HTTPS(80/443)需 ICP 备案(国内服务器,1-2 周)
3. 等解析生效(几分钟~10 分钟):`python3 -c "import socket; print(socket.gethostbyname('sync.域名'))"`
4. 改设备端 Syncthing 服务器地址:`tcp://sync.<域名>:22000`
   - **先解析生效再改,避免断连**
5. 服务器端文档/脚本批量替换:
   - **只替换 `tcp://IP:22000` 模式**,保留描述性 IP 引用(如"公网 IP {{SERVER_IP}}")
   - 排除 raw/、.obsidian/、.stversions/、技能库/ 等目录
   - backup_all.sh 的 README/scp 建议同步改域名
6. 验证三端连接(GET /rest/system/connections)

### 不用改
- 安全组/防火墙规则(端口不变)
- 微信网关(出站长连接,与域名/IP 无关)
- Clash 代理(机场订阅)
- cron prompt(无 IP 引用)

### 域名选型要点(个人用户)
- .cn:个人可注册、便宜、国内稳(首选)
- .com:最通用但贵
- .com.cn:个人一般注册不了(需营业执照)
- .top:便宜但信任度低(黑名单重灾区)
- .xyz:可用,国内偶有"非官方"提示
- 信任度机制:后缀的历史口碑影响新域名初始信任(黑名单系统按统计概率)

## 三、每日晨报/简报设计(2026-08 三次返工教训)

给用户做每日推送类 cron(晨报)时,三个教训:

1. **版本号/事实类信息必须防编造 —— 用"基准文件 + 增量检索"法**:
   - 用户两次抓到错误:晨报把 Kimi 写成 K2.6(实为 K3)、智谱写成 5.1(实为 5.2) —— agent 从搜索引擎旧文章里"猜"了版本号。
   - 解法:维护 `~/.hermes/data/model_baseline.json`(各厂商最新模型基准,经核实),prompt 铁律"版本号以基准为准,禁止猜测/编造,查不到写'待核实'"。agent 只查"是否有确凿新发布",有则更新基准,无则沿用。
   - 适用于任何"XX 最新动态"类简报(模型/价格/版本),不只晨报。

2. **检索次数过多 → 生成被截断**:逐家厂商 web_search(10 次)让任务跑 30 分钟,最终输出在中间被切断(文件里 Response 戛然而止)。合并为 2 次检索(国内一次、国外一次)后 4 分钟完成且输出完整。设计此类任务时:控制工具调用次数,输出文件要验证完整(尾行不是半句话)。

3. **输出格式 = 每条独立一行**(用户明确偏好):"条理要清晰,格式要一条一条的,不要挤在一起"。一家一行、待办一行一条,严禁多项挤在一行;微信端不要用 checkbox(打不了勾)。
