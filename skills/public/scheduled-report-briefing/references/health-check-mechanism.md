# 体检/推荐机制完整设计参考(2026-08-14 实战)

三套体检机制(习惯体检 662483e4f42e、规则体检 908c4a5722c6、流程推荐 89cbbec9ef7e)的完整实现,供未来新建同类 cron 参考。

## 一、三套机制总览

| 任务 | 时间 | 频率 | 扫描对象 | script(wrapper) |
|---|---|---|---|---|
| 习惯体检 | 周六 11:00 | 每周→4周稳定降每月 | 用户画像.md(30条)+ 基线 | habit_check.sh |
| 规则体检 | 周六 12:30 | 每周→稳定降每月 | 组织架构/员工守则/流程文档/jobs.json | rule_check.sh |
| 流程推荐 | 周日 22:00 | 每周 | cron输出/executions.db/文档滞后/技能问题/决策通道 | flow_signal_extract.sh |

## 二、习惯体检配套:指纹基线(habit_baseline.py)

作用:防止每晚 20:00 习惯整理覆盖周六体检的成果。

```python
# 核心逻辑(脚本,非 LLM 判断):
# make: 读画像"✅ 已确认的习惯与要求"小节,每条内容 sha256[:12] 存基线 JSON
# check: 对比基线 items vs 现状
#   - 条目缺失/新增/hash 变(含重写)→ "画像已被人工重构" + 锁定指令
#   - 完全一致 → "正常追加(编号续排)"
# 锁定指令:只允许追加(新编号=max+1),禁止改/删/重排旧条目
```

关键点:
- **条数对比不够**:重写陈述条数不变,必须 hash 对比
- 新编号由脚本算好注入 prompt,LLM 不数号
- agent 重构画像后跑 `habit_baseline.py make` 重新固化基线
- habit_extract.sh(习惯整理 wrapper)= 先 `habit_baseline.py check` 再 `daily_chat_extract.py --window-start 20`

## 三、7 类检查维度(两份体检共用)

1. 重复:多条说一件事 → 合并
2. 冲突:多文档说法不一
3. 过时:30 天未验证 / 场景已变(如任务时间改了文档没改)
4. 陈述准确性:含糊/误导/范围不清
5. 陈述优化:更清晰简洁 —— **只改表述,不改边界**(优化后适用边界和原版完全一样)
6. 可执行性:指向明确动作 —— **不写死具体数值/时间/穷举清单**(给判断原则,不给死列表)
7. 一致性:同义表达统一版本(如"宁缺毋滥"5 处写法不一 → 建议建工作室铁律.md 统一)

## 四、表述原则:边界完整 + 例子"不限于"

```markdown
【边界】(权威,能枚举全就写全)
"重要决策先问:①花钱 ②账号安全/隐私 ③不可逆 ④对外分享/发布 ⑤已表态事项"
【例】(帮助理解,标注"不限于",≤3个,放边界后)
例:不限于——花钱买服务、删文件、发公告
```

- 边界负责"准",例子负责"懂",例子永远声明"不限于"
- 反例:把"注意作息"改成"凌晨0-1点睡"= 写死(作息会变)

## 五、输出格式模板(三份报告统一)

```
【习惯体检 🧍】/【规则体检 📋】/【流程推荐优化 🛠️】(日期)

📌 建议(1-2条):
- 问题:第N条「原内容」| 建议:怎么改 | 成本:低/中/高
🔍 观察(≤3条):
- ...
💡 回复「X-采纳 N」我改;「X-评估 x」我出方案;无改动回「X-无」
```

铁律:只出清单不执行;每条带证据(文件路径/日期);无证据不列;总长≤15行;禁编造。

## 六、报告前缀防串号

- 习惯体检-采纳 N / 规则体检-采纳 N / 流程推荐-采纳 N
- 原因:用户可能同时留多份报告没回,过几天回"采纳 1"无法判断指哪份

## 七、落地清单

1. script 字段只填 wrapper 纯名(参数写死在 wrapper 内)——见 SKILL.md「script 字段坑」
2. 数据注入用 wrapper 输出,不用 context_from(轻量模型抄作业)
3. enabled_toolsets 只给需要的(terminal+file)
4. 建完先手动触发演示运行,用户验收后才算定稿
5. 信号提取器只扫 `## Response` 段 + 排除自身 job id(防误报)
