# 📚 工作室知识管理章程

> 所有知识产出的分类、存储、流转、维护规则。全员遵守，闭环运转。

---

## 一、核心原则

1. **写下来 > 记在脑子里**：凡是有复用价值的信息，必须落盘
2. **一处写入，多处引用**：同一信息只在一个地方维护，其他地方用链接引用
3. **按需分层**：不是所有东西都要写——按"是否复用 × 多久用一次"决定投入
4. **闭环可追溯**：每条知识有来源、有责任人、有刷新周期、有退役规则

---

## 二、知识分类体系

### 2.1 按生命周期分

| 类型 | 定义 | 生命周期 | 举例 |
|---|---|---|---|
| **运营知识** | 日常工作产生的过程记录 | 按日期归档，不主动删除 | 复盘、日志、用量、日报 |
| **资产知识** | 有长期参考价值的沉淀 | 永久保留，定期刷新 | 流程文档、实体页、技能 |
| **临时交付物** | 为特定任务产出的一次性文档 | 交付后按规则处理 | PDF、临时报告、草稿 |

### 2.2 按内容性质分

| 类型 | 存储位置 | 写入者 | 刷新周期 |
|---|---|---|---|
| **用户画像** | `vault/wiki/entities/用户画像.md` + Memory MCP | 军师（习惯整理cron） | 每日追加 |
| **流程文档** | `vault/流程/` | 军师/当事人 | 首次跑通时写，流程变更时更新 |
| **实体页** | `vault/wiki/entities/` | 军师/知远/墨白 | 有新信息时更新 |
| **概念页** | `vault/wiki/concepts/` | 军师/知远 | 首次定义时创建 |
| **对比页** | `vault/wiki/comparisons/` | 知远 | 需要方案对比时创建 |
| **调研报告** | `vault/工作室产出/方案架构师·知远/调研报告/` | 知远 | 永久保留原稿 |
| **写作产出** | `vault/工作室产出/写作员·墨白/` | 墨白 | 永久保留原稿 |
| **复盘** | `vault/复盘/员工/<岗位>/` | 各员工自己 | 每单必写 |
| **技能** | `~/.hermes/skills/` | 军师 | 有踩坑/优化时 patch |
| **原始素材** | `vault/wiki/raw/` | 知识库整理cron | 永久保留，只读不改 |

## 三、产出生命周期（闭环）

```
┌─────────────────────────────────────────────────────────┐
│                    员工接到任务                            │
│                        ↓                                │
│                    执行任务                               │
│                        ↓                                │
│              ┌─────────────────────┐                    │
│              │  产出 MD 文档        │                    │
│              │  存工作室产出/<岗位>/ │                    │
│              └─────────┬───────────┘                    │
│                        ↓                                │
│              ┌─────────────────────┐                    │
│              │  写复盘              │                    │
│              │  存复盘/员工/<岗位>/  │                    │
│              └─────────┬───────────┘                    │
│                        ↓                                │
│              ┌─────────────────────┐                    │
│              │  Ingest 到 wiki      │                    │
│              │  raw/entities/       │                    │
│              │  concepts/           │                    │
│              │  comparisons/        │                    │
│              └─────────┬───────────┘                    │
│                        ↓                                │
│              ┌─────────────────────┐                    │
│              │  转 PDF（如需要）     │                    │
│              │  发微信给老大         │                    │
│              └─────────┬───────────┘                    │
│                        ↓                                │
│              ┌─────────────────────┐                    │
│              │  PDF 发完即删        │                    │
│              │  MD 永久保留         │                    │
│              └─────────────────────┘                    │
└─────────────────────────────────────────────────────────┘
```

### 3.1 产出目录（永久保留 MD）

| 员工 | 产出目录 | 复盘目录 |
|---|---|---|
| 知远 | `vault/工作室产出/方案架构师·知远/调研报告/<主题>/` | `vault/复盘/员工/方案架构师·知远/` |
| 墨白 | `vault/工作室产出/写作员·墨白/` | `vault/复盘/员工/写作员·墨白/` |
| 技术员·Claude | `vault/工作室产出/技术员·Claude/` | — |
| 军师 | 无专门产出目录（调度+文档整理） | `vault/复盘/军师/` |

### 3.2 wiki 知识库（团队共用）

| 目录 | 用途 | 规则 |
|---|---|---|
| `wiki/entities/` | 实体页（工具、配置、工作流） | 有则更新，无则新建 |
| `wiki/concepts/` | 概念页（技术、方法） | 首次定义时创建 |
| `wiki/comparisons/` | 对比页（方案 A vs B） | 需要对比时创建 |
| `wiki/raw/` | 原始素材（调研报告副本） | 只读不改，增量追加 |
| `wiki/index.md` | 总目录 | 每次 ingest 后更新 |
| `wiki/log.md` | 操作日志 | 每次操作后追加 |

### 3.3 临时交付物（用完即删）

| 类型 | 处理方式 |
|---|---|
| PDF（微信交付） | 发完即删，不入库 |
| 临时草稿 | 任务完成后删，或归入产出目录 |
| 测试文件 | 验证通过后删 |

## 四、各场景文档规范

### 4.1 调研任务结束

**必写：**
1. 调研报告 → `工作室产出/方案架构师·知远/调研报告/<主题>/YYYY-MM-DD-主题.md`
2. 复盘 → `vault/复盘/员工/方案架构师·知远/YYYY-MM-DD-<主题>经验总结.md`

**选写（有价值时）：**
3. Ingest 到 wiki：raw/ + entities/concepts/comparisons
4. 流程文档 → `vault/流程/`（如果调研发现新流程）
5. 技能沉淀 → skill（如果发现可复用方法）

### 4.2 写作任务结束

**必写：**
1. 文章 → `vault/工作室产出/写作员·墨白/`
2. 复盘 → `vault/复盘/员工/写作员·墨白/YYYY-MM-DD-<主题>经验总结.md`

**选写：**
3. 风格库更新（如果用户反馈了新偏好）
4. 合规规范更新（如果踩了新坑）

### 4.3 技术方案落地

**必写：**
1. 复盘 → `vault/复盘/军师/YYYY-MM-DD-军师复盘.md`

**选写（首次实现时建议写）：**
2. 从零到落地教程 → `vault/流程/从零搭建手册/`
3. 流程文档 → `vault/流程/`
4. wiki 实体页 → `vault/wiki/entities/`

### 4.4 问题排查

**必写：** 无（简单问题口头说就行）

**选写（非trivial的bug建议写）：**
1. 排障记录 → `vault/wiki/entities/`（如微信限流排障记录）
2. 技能补丁 → `~/.hermes/skills/`（如 weixin-gateway-ops）

## 五、透明化规则

### 5.1 "记下了"必须带位置

| 场景 | ❌ 错误说法 | ✅ 正确说法 |
|---|---|---|
| 记住用户偏好 | "好的，我记下了" | "记到用户画像 #66 了（`vault/wiki/entities/用户画像.md`）" |
| 写复盘 | "已总结经验" | "经验写到复盘了（`vault/复盘/员工/方案架构师·知远/2026-08-17-xxx.md`）" |
| 沉淀技能 | "这个我记住了" | "写成 skill 了（`voice-cloning-best-practices`）" |
| 更新流程 | "流程已更新" | "流程文档已更新（`vault/流程/知远调研工作流.md`）" |

### 5.2 派活时必须包含

1. **产出路径**：明确告诉员工文件存哪
2. **复盘要求**：明确告诉员工写复盘
3. **格式要求**：条目式/正文/代码等

### 5.3 晨报统计规则

- 只统计 `工作室产出/` 下的文件（排除 wiki/ 自动整理）
- 时间窗口：昨天 08:00 → 今天 08:00（凌晨算"昨晚"）
- 按员工分组，列出全部产出（不只列1条）

## 六、维护机制

### 6.1 自动维护

| 任务 | 频率 | 执行者 | 内容 |
|---|---|---|---|
| 知识库整理 | 每天 3:30 | cron | wiki 归档、index 更新 |
| 习惯整理 | 每天 2:00 | cron | 画像更新、SOUL 同步 |
| 目录更新 | 每天 4:30 | cron | 技能目录、知识库目录 |
| 晨报推送 | 每天 8:00 | cron | 用量/待办/产出/健康 |

### 6.2 人工维护

| 事项 | 频率 | 负责人 |
|---|---|---|
| 流程文档审核 | 每周日 12:30 | 军师（规则体检） |
| 技能健康检查 | 每周六 10:00 | 军师 |
| SOUL 周审 | 每周日 10:00 | 军师 |
| 复盘质量评估 | 每周日 0:45 | 军师（周复盘） |

### 6.3 知识退役规则

| 类型 | 退役条件 | 处理方式 |
|---|---|---|
| 临时交付物 | 交付完成 | 删除 |
| 过期调研报告 | 被新版本替代 | 标记"已过期"，保留不删 |
| 过时流程文档 | 流程已变更 | 更新为新版本，旧版移入 `archive/` |
| wiki 实体页 | 实体已不存在 | 标记"已废弃"，保留不删 |

## 七、质量标准

### 7.1 调研报告

- 每条关键结论必须带来源（URL），无来源不写
- 条目式输出，每条独立一行
- 版本号/数据以基准或官方为准，不猜
- 写完自检：有没有无来源的断言？有没有可能过时的信息？

### 7.2 复盘

- 学到什么（新知识/新方法）
- 反馈模式（用户怎么评价的）
- 暴露问题（哪里卡住了/哪里做错了）
- 下次 checklist（下次做类似任务的检查项）
- 一句话宣言（最核心的教训）

### 7.3 流程文档

- 必须有流程图（mermaid）
- 必须有"为什么"（不只是"怎么做"）
- 必须有注意事项/踩坑记录
- 定期审核是否过时

## 八、反模式（禁止事项）

1. ❌ **说"记下了"不带位置** → 必须透明化
2. ❌ **产出不存文件** → 必须写入产出目录
3. ❌ **长任务不写复盘** → 每单必写
4. ❌ **wiki 和产出目录混为一谈** → 两个定位不同
5. ❌ **PDF 入库** → PDF 发完即删，只留 MD
6. ❌ **流程只在脑子里** → 必须写成文档
7. ❌ **派活不写产出路径** → prompt 必须明确
8. ❌ **复盘编造/敷衍** → 必须基于真实经历
